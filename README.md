# ALETHEIA

ALETHEIA היא פלטפורמת מחקר אקדמית לניתוח האופן שבו כלי תקשורת מתמודדים עם
אירועים שנויים במחלוקת ומתפתחים בזמן. המערכת בוחנת את המתח בין נאמנות למידע
שהיה ניתן לדעת בזמן הפרסום לבין עוצמת המסגור שבאמצעותה הכתבה מארגנת את
המציאות לכדי נרטיב ברור.

המערכת נבנתה לצורכי סמינר מחקרי. היא אינה מוצר SaaS, אינה מערכת לקביעת
“אמת מוחלטת”, ואינה מנסה להסיק כוונת זדון או לקרוא את מחשבות הכתב.

## שאלת המחקר והמדדים

השאלה האופרטיבית היא:

> כיצד כלי תקשורת בוחרים, מנסחים, מייחסים, מארגנים ומעדכנים טענות עובדתיות,
> ואילו צירופים של נאמנות לאמת ועוצמת מסגור נוצרים בין קייסים, שפות, שלבי זמן
> וגופי תקשורת?

התוצאה המרכזית היא מפה דו־ממדית, לא ציון משוקלל יחיד:

- **T — Truth fidelity:** התאמה לעוגנים שהיו זמינים בזמן הפרסום, שקיפות
  המקורות, מידת ודאות התואמת לידע הזמין ותיקון לאורך זמן.
- **F — Frame intensity:** עד כמה הכתבה בונה מסגרת פרשנית בולטת, עקבית
  ומאורגנת. ציון גבוה אינו מעיד כשלעצמו על אמת, שקר, איכות או הטיה פסולה.
- **דגלי חריגה:** סימון ביקורת בלבד למקרים חריגים שבהם קיימת סטייה חמורה,
  קונקרטית וניתנת להוכחה מן התשתית העובדתית. זה אינו ציר תוצאה ואינו
  מוכיח כוונה.

הארכיטקטורה המתודולוגית הנוכחית היא `TF-2D/1.0`. ציון `A` המשוקלל שהיה
קיים בגרסאות מוקדמות הוסר משכבת הביצוע. שדות תאימות ישנים נשארים ריקים
במעטפת האחסון בלבד ואינם תוצאה מחקרית.

## זרימת העבודה

```text
הצעת קייס
    ↓  שער אנושי 1: אישור הנושא
גילוי ובניית סל כתבות
    ↓  שער אנושי 2: אישור הסל
איסוף וסנפשוטים → בדיקת התאמת נושא → ניתוח T ו-F
    ↓
בחינה אוטונומית נוספת של מחלוקות
    ↓  רק סתירות מהותיות וקשות
חדר שיפוט אנושי
    ↓
סגירת הקייס → תוצאות ודשבורדים → סנכרון לענן
```

ברירת המחדל המחקרית היא 27 כתבות לקייס: שלוש שכבות שיח, שלושה גופי
תקשורת בכל שכבה ושלושה חלונות זמן. החלפת מקור מותרת לפי חוזה הדגימה, תוך
שמירה על שפה, שכבה ופרופיל מערכתי דומים.

## מה כולל הממשק

יישום Streamlit המקומי כולל:

- מחולל קייסים ושני שערי אישור אנושיים;
- מעקב אחר בניית סל הכתבות והפעלת הפייפליין;
- חדר שיפוט לחריגים בלבד, כולל ראיות, תרגום ומדיה זמינה;
- ספר תקדימים שממיר הכרעות אנושיות למדיניות עתידית;
- מעקב אחרי `T4`, כלומר תיקון ועדכון לאורך זמן;
- דשבורדים ברמת קייס ובחתך רב־קייסי;
- טבלת ציונים ונימוקים לצורכי שקיפות וביקורת מחקרית.

## מבנה המאגר

| נתיב | תפקיד |
| --- | --- |
| `app.py` | ממשק המחקר וחדר השיפוט |
| `aletheia_lite/` | ליבת האיסוף, יצירת הקייסים, הניתוח, השיפוט והתוצאות; זוהי שכבת הקוד הפעילה היחידה |
| `measurement/` | חוזי המדידה, ספרי החוקים, סכמות ומתאמי שפה |
| `config/` | תצורות מחקר ודוגמאות לדגימה |
| `case_generator/` | סכמות ודוגמאות של מחולל הקייסים |
| `scripts/` | פקודות הפעלה, בדיקה, סגירה וסנכרון |
| `tests_lite/` | בדיקות לא־מקוונות של הפלטפורמה הפעילה |
| `cloud/` | חוזי BigQuery/GCS שאינם מכילים מפתחות |
| `bibliography/` | סכמות ורשימות מקורות מחקריות ועיתונאיות |

קורפוס הכתבות, HTML גולמי, מסדי נתונים, החלטות שיפוט, תוצרי מודל ותוצרי
ענן אינם חלק ממאגר הפלטפורמה הציבורי. הם נשמרים מקומית או בשכבת הענן
הפרטית ומוגנים באמצעות `.gitignore`.

## הפעלה מקומית

דרישות בסיס: Python 3.11 ומעלה וחשבון Google Cloud רק עבור פעולות Vertex AI,
BigQuery או Cloud Storage.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
cp .env.example .env
```

לאחר הזנת הערכים המקומיים ב־`.env`:

```bash
streamlit run app.py --server.port 8505
```

הרצת חבילת הבדיקות המקומית:

```bash
python3 -m unittest discover -s tests_lite -v
```

חבילת הבדיקות שבמאגר הציבורי ניידת ואינה דורשת גישה לקורפוס המחקר הפרטי.
היא מבוססת על fixtures סינתטיים או מורשים. בדיקות אינטגרציה הקשורות
לקייסים, להכרעות ולסנפשוטים נשארות בסביבת המחקר המקומית ואינן נכללות
במאגר הציבורי.
